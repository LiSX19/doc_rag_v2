二、项目要求
2.1 选题范围
基于大语言模型构建一个完整、可运行的 AI 应用系统。选题应具有明确的应用场景与实际价值。每组选择不同方向，鼓励差异化创新。
参考方向（不限于此）：
#	选题方向
1	知识问答系统：基于 RAG 的垂直领域问答（教育/医疗/法律/金融/企业知识库）
2	AI 辅助编程平台：多 Agent 代码审查（审查→安全→风格→汇总），RAG 对接项目文档，MCP 集成 Git
3	文档分析平台：多格式文档解析、摘要生成、结构化信息提取（支持多模态）
4	多 Agent 协作应用：自动化研究助手、智能客服系统、数据分析 Agent
5	MCP 工具生态平台：整合多种 MCP Server 的统一 AI 工具入口
6	AI 辅助教学/学习系统：RAG 课程材料 + 多模态 + 个性化 Agent（讲解/出题/评测）
7	数据分析 Agent：自然语言查询数据库、自动生成分析报告与可视化
8	创新应用：其他有创意的 LLM 应用方案（需教师审批）
2.2 技术要求
项目必须综合运用课程所学的至少 3 项核心技术：
Prompt Engineering（提示工程）
Vibe Coding（AI 辅助开发工具，如 Cursor / Claude Code）
MCP 协议集成
RAG 系统（检索增强生成）
AI Agent（工具调用 / 多步推理 / LangGraph）
多模态处理
模型微调（LoRA / QLoRA）
安全护栏（输入过滤 / 输出检测）
额外要求：
必须包含 Web 交互界面（Gradio / Streamlit / 自定义前端）
鼓励使用 Vibe Coding 工具辅助项目开发
2.3 TDD-for-AI 要求
本课程引入 TDD-for-AI（AI 系统的测试驱动开发）作为核心工程方法论。项目须包含测试体系：
基础要求（所有组必须完成）：
为项目核心功能编写 ≥ 10 个 pytest 测试用例
测试须覆盖至少 2 个层级（以下任选）：
工具测试：MCP 工具功能验证（输入 → 输出是否符合预期）
检索测试：RAG 检索质量评估（使用 RAGAS 或自定义指标）
行为测试：Agent 决策轨迹验证（是否调用正确工具、是否正确终止）
安全测试：注入攻击 / 越狱测试（系统是否正确拒绝）
集成测试：端到端场景验证（用户输入 → 最终输出是否合理）
进阶加分（推荐）：
提交 requirements_test.py 作为可执行需求规约 —— 用测试用例精确定义系统“应该做什么”
测试覆盖 ≥ 3 个层级
包含测试通过率统计与评估数据
什么是可执行需求规约？传统需求文档用 Word 描述“系统应能查询天气”。可执行规约用测试代码表达同样的需求：assert system.query("深圳天气") 返回包含温度的结构化数据。测试即需求，运行即验证。

四、评分标准
期末项目（占课程总分 50%）按以下 5 个维度评分：
维度	权重	A（90-100）	B（80-89）	C（70-79）	D / F（<70）
架构深度	25%	综合运用 4+ 技术，多 Agent + MCP + RAG 完整集成	综合运用 3 项技术，方案合理	运用 2 项技术，基本可行	技术单一或方案不合理
TDD-for-AI	20%	20+ 测试用例，覆盖行为/检索/安全等 3+ 层级	10+ 测试用例，覆盖 2 个层级	5+ 基础测试用例	无测试或测试无法运行
创新性	15%	选题新颖，方案有独创性	选题有一定新意	选题常见但有个人思考	选题平庸，缺乏创新
完成度 + Demo	25%	功能完整，现场演示流畅，能处理边界情况	核心功能完整，Demo 基本流畅	基本功能可用，Demo 有小问题	功能不完整或无法演示
安全	15%	对自身系统做了安全测试	做了基本安全测试	有安全意识但测试不充分	未考虑安全性
与传统评分的关键区别：TDD-for-AI 质量单独占 20%。这意味着一个功能完美但没有测试的项目最高只能拿 80 分。测试是 AI 系统工程化的核心能力。

六、注意事项
1. 禁止抄袭
项目代码须原创，引用的开源代码须注明出处。
2. 个人贡献
每位成员须在报告中说明个人贡献。
3. 版本控制
鼓励使用 Git 进行版本控制，提交时附 commit 历史。
4. 答辩参与
答辩时每位成员都须参与汇报或回答问题。缺席答辩者该项成绩记为 0 分。
5. AI 工具使用
鼓励使用 Vibe Coding 工具（Cursor / Claude Code）辅助开发，但需在报告中说明 AI 工具的使用方式与贡献比例。
6. 测试代码与 AI
测试代码可以借助 AI 工具辅助编写，但须理解每个测试用例的含义并能在答辩时解释。
7. 延迟提交
迟交每天扣 10 分，最多 3 天；超过 3 天该项成绩记为 0。最后截止提交日期为 4 月 30 日。
七、常见问题
Q1. 团队可以只有1人吗？
可以。
Q2. 可以使用付费 LLM API（OpenAI / Anthropic）吗？
可以，但系统必须同时支持本地 Ollama 模型，以便教师在没有你 API Key 的情况下也能验证。
Q3. 必须使用 RAG 吗？
不强制。但必须使用列出的至少 3 项核心技术，RAG 只是其中一项。
Q4. 报告字数下限只有 3000 字，会不会被认为“内容太薄”？
不会。3000 字是字数下限，重点在于内容质量与代码实现。如果你的项目实现扎实、测试充分、分析有深度，3000-4000 字完全可以拿高分。反之，如果项目本身做得不够，即使写到 8000 字也无法弥补。
